# 多语言（i18n）架构与维护规则

> 本文是 `dsh-workload-report` 六国语言（日 / 西 / 法 / 德 / 俄 / 葡）接入后的长期维护手册。
> 目标：**新增一条文案只改一种文件；新增一种语言只动一处注册。**

## 1. 结论先行

- DSH 0.2.2 起内置 8 种界面语言：`zh`、`en`、`ja`、`es`、`fr`、`de`、`ru`、`pt`。
  用户设置里的「语言」切换后，`ctx.locale` 快照的 `active` 就是上述 id 之一，插件实时跟随，无需重载。
- 插件文案**只有一份来源**：`src/locales/*.json`（JSON 词典）+ `src/locales/index.js`（注册表与翻译函数）。
  客户端面板、宿主路由、AI 画像全部从这一份词典取文案。
- 插件把 8 部词典整体注册进宿主 locale 服务：`ctx.locale.register(NS, dictionaries)`。
  DSH 的 8 种语言由宿主自己提供（`addLanguage`），插件**不要**再调用 `addLanguage`，否则重复注册会抛错。
- `zh.json` 是键集基准；其余 7 种语言必须与它**逐键一致、占位符一致**，由 `npm run check:i18n` 强制。
- 当前状态（2.5.0）：8 种语言 **366 键全部翻译完成**；`npm test` 1625 条离线断言 + 85 条 i18n 检查全绿；
  `test/e2e-i18n.mjs` 在真实浏览器里逐语言验收看板与报告页。

## 2. 目录与职责

| 路径 | 职责 |
|---|---|
| `src/locales/index.js` | 注册表：`NS` / `LOCALES` / `dictionaries` / `languageOf` / `localeTag` / `translate` / `translator` |
| `src/locales/zh.json` | 中文词典（**键集基准**，新键先加这里） |
| `src/locales/en.json` | 英文词典（兜底语言，必须与 zh 同步） |
| `src/locales/{ja,es,fr,de,ru,pt}.json` | 六国语言词典（键集、占位符、键顺序与 zh 一致） |
| `src/client/index.jsx` | `useLocale()`：订阅 `ctx.locale` 快照 → `{ lang, t }`；`apply()` 注册 8 部词典 |
| `src/ai-profile.js` / `src/profile-service.js` | 本地规则画像与模型提示词按请求语言生成 |
| `test/i18n.mjs` | 离线一致性检查（键集 / 占位符 / 空值 / 硬编码文案 / JSON 合法性） |
| `test/e2e-i18n.mjs` | 真实浏览器端到端：8 种语言下打开面板并校验渲染文案 + 截图 |

> **README 命名约束**：仓库根目录只放英文 `README.md`；各语言搜索落地页在
> `docs/i18n/README.<lang>.md`。原因：npm 用 glob `{README,README.*}` 选首页正文，
> 根目录多个 README 时可能选中非英文版本（实测会选中中文）。

## 3. 运行期两种取文案方式

```js
import { translator, languageOf, localeTag } from "../locales/index.js";

// A. 客户端：订阅宿主 locale 快照（组件里）
const { lang, t } = useLocale();          // lang = "de" 这类已归一化的语言 id
t("kpi.tokens");                           // → "Token gesamt"

// B. 宿主：按请求语言创建一个翻译函数（无 React、无宿主依赖）
const t = translator(languageOf(requested));
t("profile.title");
```

- 查找顺序：当前语言 → `en` → 键名本身。未知语言（例如以后 DSH 新增但插件未翻译）自动回落英文，不会显示键名或中文。
- `languageOf("pt-BR")` → `pt`；`languageOf("ko")` → `en`。
- 日期格式统一用 `localeTag(lang)`（zh→`zh-CN`、pt→`pt-BR`……），不要再手写 `"zh-CN"`。
- 数字 / Token / 金额格式沿用 `src/format.js` 的固定英文紧凑格式（`1.50 K`），与 DSH 自身口径一致，不随语言变化。

## 4. 文案写作硬规则

1. **整句一个键，禁止拼接。** 不同语言语序不同，`前缀 + 变量 + 后缀` 必然翻译错。
   - ✅ `"kpi.active.sub": "模型 {llm} · 工具 {tool}"`
   - ❌ `t("kpi.active.model") + " " + hours + t("kpi.active.tool")`
2. **占位符原样保留**：`{name}` 大小写、数量、顺序都不许改；翻译时只改占位符之间的文字。
3. **只放展示文案**：日志、内部错误码说明、JSON 字段名、口径文档链接不进词典。
4. **不翻译专有名词**：`DSH`、`DeepSeek`、`Token`、`GitHub`、`Gitea`、`COS`、`HTML`、`KPI`、`TTFT`、`API`、`Git`、`Chrome`、`hostname`、仓库名等保持原样。
5. **不写死常量文案**：客户端组件里不允许出现中文 / 英文句子字面量，一律走 `t()`；由 `test/i18n.mjs` 静态扫描兜底。
6. **计数句用「无变形」写法**：DSH locale 服务不提供复数规则；俄语、葡语等对数量敏感的句子，
   翻译成「已推送会话数：{n}」这类不会因 n 变化的句式，或让译者选择中性表达。
7. **标点与空格**：保留 ` · `、`…`、`：` 等排版符号的语义位置；中文冒号 `：` 在其它语言改成对应标点。

## 5. 服务端与报告的「语言从哪来」

宿主半部不持有界面语言，语言必须由客户端显式带上：

| 入口 | 语言来源 |
|---|---|
| `GET /workload-report/v1/profile` | query `lang`（画像卡请求时写当前 `lang`） |
| 同步设置 / 自检 / 推送错误 | 服务端只回稳定 `code` + `params`，客户端用 `sync.err.<code>` 渲染；旧字段 `message` 仅作日志与兜底 |
| 服务端日志 | 固定中文（内部诊断，不进词典、不面向用户） |

## 6. 新增一条文案

1. 在 `src/locales/zh.json` 加键（键名用点分层级：`域.对象.语义`，如 `report.cacheHitRate`）。
2. 在 `src/locales/en.json` 加同名键（英文）。
3. 在代码里用 `t("report.cacheHitRate")` 引用。
4. 六国语言词典补同一键（可先跑 `npm run check:i18n` 看缺哪些语言）。
5. `npm run check:i18n` + `npm test` 必须全绿。

## 7. 新增一种语言（例如韩语 `ko`）

1. 复制 `en.json` → `ko.json` 并逐键翻译（保持键顺序）。
2. `src/locales/index.js`：`LOCALES` 末尾加 `"ko"`、`LOCALE_TAGS` 加 `ko: "ko-KR"`、补 `import ko from "./ko.json" with { type: "json" }` 与 `dictionaries` 条目。
3. 若 DSH 宿主**尚未**内置该语言：由插件在 `apply()` 里调用一次
   `ctx.locale.addLanguage({ id: "ko", label: "한국어", fallback: "en" })`（宿主已内置时不要调用，会重复报错）。
4. 重新构建 `lib/client.js`（`npm run build`）并跑 `test/e2e-i18n.mjs`。

## 8. 翻译工作流（协作 / 外包）

- 词典是 JSON：译者只改 `src/locales/<lang>.json`，不需要读代码。
- 每批文案的上下文（键 + 中文 + 英文 + 使用界面）由 `docs/i18n-glossary.md` 与源文件提供。
- 提交前译者自检：`node test/i18n.mjs --lang <lang>`。
- 术语表（Token / workspace / session / turn / step / cache / sync / credential / KPI…）见 `docs/i18n-glossary.md`。
- 机翻初稿必须人工（或第二次模型）校一遍：占位符、数字单位、按钮文案长度（德语 / 俄语通常比中文长 30–50%）。

## 9. 验收清单

```bash
npm run build          # lib/client.js 含 8 种语言词典
npm run check:i18n     # 85 项：8 语言键集/顺序/占位符/空值/漏译/零宽字符/写死文案/死键
npm test               # 1625 条离线断言 + 上面的 i18n 检查
./test/e2e-boot.sh 3299 > .tmp/e2e-boot-3299.log 2>&1 &   # 隔离实例（独立 DSH_HOME / 端口）
node test/e2e-i18n.mjs # 8 种语言真实浏览器：看板，逐语言截图
```

- 看板：8 种语言下标题 / 页签 / KPI / 区间 / 范围下拉 / 同步弹窗文案等于词典值，无裸露键名、无串台。
- AI 画像：本地规则版与模型版输出均跟随语言；模型失败时回落本地规则，界面不出现中文残留。
